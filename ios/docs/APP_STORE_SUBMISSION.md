## Description (draft — edit to taste)

> Planter is a calm, private journal for the plants you live with.
>
> Add each plant, photograph it as it grows, and watch the story build: a progress timeline, a before-and-after comparison slider, care notes, and a health score that nudges you when something needs attention.
>
> Ask the built-in assistant about watering, light, yellow leaves, pests, repotting, or propagation. On iPhones with Apple Intelligence, answers are generated by Apple's on-device model and grounded in your plant's own journal — nothing you write or photograph ever leaves your phone. On other iPhones, a built-in care guide answers instantly, fully offline.
>
> • Photo growth timeline with before/after compare
> • Care reminders that arrive the day care is due
> • Private, on-device AI plant help — no account, no cloud
> • Health score and status tracking per plant
> • One-tap JSON backup you control
> • A design with marigold roots, inspired by the gardens of Punjab and Mexico
>
> Planter is local-first: no sign-up, no subscription, no analytics. Your garden is yours.

## Privacy

- **Privacy policy URL**: host `PRIVACY_POLICY.md` publicly (GitHub Pages on this repo is the easy path) and paste the URL.
- **App privacy questionnaire**: select **"Data Not Collected"** for everything. This is true: no analytics, no accounts, no server. It must stay true — adding any analytics SDK later means redoing this section.
- **Export compliance**: the app uses only exempt encryption (HTTPS/OS). `ITSAppUsesNonExemptEncryption = NO` is already set in the project, so App Store Connect should not even ask. If it does, answer: uses encryption → only exempt/standard.

## App Review notes (paste into the "Notes" box)

> Planter is a fully offline, local-first plant care journal. There is no login and no server.
>
> The "Assistant" tab uses Apple's on-device Foundation Models framework (Apple Intelligence) when available on the device. On devices without Apple Intelligence, it falls back to a built-in rule-based plant-care guide bundled in the binary. No AI requests leave the device, which is why there is no API key or network traffic to review.
>
> Camera permission is requested only when the user takes a progress photo. Notifications are requested only when the user sets a care reminder.

## Screenshots

Required set: 6.9" display (iPhone 16/17 Pro Max simulator works). One set is enough; iPad screenshots only if you keep iPad support checked.

Suggested shots (in this order):
1. Garden grid with several plants (add 3–4 plants with photos first)
2. Plant detail — hero photo + health score + care controls
3. Before/after photo comparison slider mid-drag
4. Assistant chat answering a watering question (banner visible)
5. Progress timeline with 3+ photos
6. Settings — privacy section ("All data stays on this device")

Tips: use real plant photos, set the simulator to 9:41, light mode for the main set (add dark variants if you have time).

## Future monetization (do NOT do these in v1)

- Don't mention Pro, subscriptions, or "coming soon" features anywhere in metadata — reviewers flag it.
- When ready: the code already gates features through `FeatureGate.swift`; add a StoreKit 2 entitlements provider + paywall, create the in-app purchase in App Store Connect, and flip `FreeForNowEntitlements` to the StoreKit provider.

## Common rejection risks (already handled, for awareness)

- **4.2 Minimum functionality**: native SwiftUI app with camera, notifications, on-device AI — comfortably above the bar.
- **2.1 Crashes**: run through the MAC_CHECKLIST test pass on a real device before submitting.
- **5.1.1 Permission strings**: camera usage string is set; notifications asked contextually.
- **AI claims**: the app never claims cloud AI; the banner honestly labels which mode is active.
